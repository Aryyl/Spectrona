Everyday Health Intelligence

A wearable IoT-based health monitoring system engineered to capture vital physiological signals during daily life, validate them at the edge, and provide real-time visibility to caregivers and clinicians.

THE CORE MISSION

Bridging the Gap Between Clinic Visits and Daily Life

Instead of checking a person's health measurements only during occasional visits to a hospital or clinic, Jeev One monitors selected health indicators continuously during everyday activities. The wearable collects multi-parameter telemetry, validates it locally via a Raspberry Pi 5 edge gateway, and synchronizes eligible records to Firebase Cloud Firestore so authorized caregivers and doctors can review real-time and historical trends from anywhere.

// SECTION 1: END-TO-END PIPELINE

The Complete System Architecture

The system combines wearable sensing, edge computing, and cloud monitoring into a robust, synchronized data pipeline.

STAGE 01 / WEARABLE SENSING
TRANSDUCER LAYER

Wearable Sensors

Collects multi-parameter biometric and environmental signals during everyday activities: heart rate/ECG, blood oxygen (SpO₂), body temperature, room temperature, and relative humidity.

• AD8232 ECG / HR Module • MAX30102 Optical SpO₂ • MLX90614 Infrared Temp • DHT22 Ambient Monitor
STAGE 02 / MICROCONTROLLER
DATA PACKETIZATION

ESP32 Controller

Reads connected sensors in scheduled timed slots, synchronizes its clock using NTP so readings have valid Unix timestamps, formats JSON packets, and publishes to MQTT over Wi-Fi.

• NTP Clock Synchronization • Scheduled Timed Polling • Wi-Fi MQTT Publisher • Topic: health/sensors
STAGE 03 / EDGE COMPUTING
VALIDATION & RISK ENGINE

Raspberry Pi 5 Gateway

Mosquitto broker receives MQTT messages on port 1883. The gateway validates timestamps, checks numeric ranges, stores records in SQLite with patient associations, derives composite risk scores, and manages the cloud sync outbox.

• Mosquitto MQTT Broker (1883) • Local SQLite Database Storage • Rule-Based Tri-Domain Risk • Systemd Background Daemon
STAGE 04 / CLOUD LAYER
CLOUD FIRESTORE

Firebase Cloud Storage

Stores synchronized sensor records and derived risk classifications in the patient_readings collection. Enables remote access from any location without opening local Pi ports.

• Collection: patient_readings • Timestamp & Patient ID Index • Outbox Retry Queue Sync • Secure Remote Accessibility
STAGE 05 / CLIENT ACCESS
PROGRESSIVE WEB APP

Web Dashboard (PWA)

Displays live real-time vitals, Lead-I ECG strip diagnostics, historical telemetry tables, dynamic baseline calibration, and alarm indicators to authorized caregivers and clinicians.

• Realtime onSnapshot Streaming • Mobile PWA Touch Optimized • Multi-Patient Profile Switching • Offline App Shell Resilience

// SECTION 3 & 4: EMBEDDED & EDGE ENGINEERING

What We Built on the ESP32 & Raspberry Pi 5

How our firmware and edge gateway turn raw electrical signals into validated, synchronized clinical records.

01 / WEARABLE CONTROLLER

What We Have Done with the ESP32

The ESP32 is the wearable's data-collection and communication controller between the sensors and the Raspberry Pi:

  • • Reads sensors in timed slots to conserve battery.
  • • Consolidates readings into a standardized JSON packet.
  • • NTP Clock Synchronization: Fixed the timestamp: 0 issue; now publishes valid Unix timestamps so the gateway accepts all readings.
  • • Connects over Wi-Fi MQTT: Publishes to health/sensors with verified successful transmission.
MQTT PAYLOAD • health/sensors VERIFIED FORMAT 
{
  "device_id": "patient_01",
  "timestamp": 1792414171,
  "heart_rate": 75,
  "spo2": 97,
  "body_temperature": 36.5,
  "room_temperature": 27.3,
  "humidity": 52.1
}
02 / EDGE INTELLIGENCE GATEWAY

What We Have Done with the Raspberry Pi 5

The Raspberry Pi 5 acts as the local gateway and edge-computing unit—more than just a bridge to the cloud:

  • • MQTT Broker (Mosquitto): Receives sensor packets on port 1883 and subscribes to health/sensors.
  • • Validation & Plausibility: Validates timestamps, numeric types, and physiological limits before recording.
  • • Local SQLite Database: Stores historical readings and patient profiles (Patient 1 and Patient 2) completely offline.
  • • Rule-Based Risk Processing: Derives vital strain, heat stress, and respiratory risk indicators with recommendations.
  • • Background Cloud Sync: Outbox queue uploads eligible patient records to Firebase Firestore with automatic retries.
  • • Systemd Auto-Start Daemon: Configured as an enabled system service that boots automatically on power-up.

DEPLOYMENT INSIGHTS

Bridging edge embedded engineering and everyday clinical care. Here is how Jeev One transitions from hardware prototype to real-world impact.

PRIMARY DEPLOYMENT FOCUS

Older Adults & Independent Living

Strongest initial fit. Designed for older adults living alone or in assisted living facilities. Collects selected vital signs (heart rate, SpO₂, body temperature, and ambient heat index) continuously during everyday routines, retaining a private history and providing remote visibility to family members and caregivers without requiring frequent clinic visits.

CLINICIAN-GUIDED EXPANSION

Chronic Conditions & Post-Op Recovery

Suitable under physician direction for patients with hypertension (once cuff hardware is validated), chronic respiratory conditions requiring longitudinal SpO₂ monitoring, or patients convalescing at home under a structured care plan.

CLEAR CLINICAL BOUNDARIES

Who It Is NOT Built For

Jeev One is a monitoring-support platform, not certified ICU hardware. It should never be used for continuous life-critical emergency alerts or as a replacement for emergency medical care.

STEP 01 // WEARABLE SENSING

Passive Everyday Monitoring

The patient wears the unobtrusive ESP32 module. Sensors sample ECG rhythms, pulse oximetry, infrared core temperature, and ambient room conditions in scheduled low-power cycles without user intervention.

STEP 02 // EDGE COMPUTING

Raspberry Pi 5 Local Ingestion

Readings are broadcast via Wi-Fi MQTT to the local Pi 5. The edge gateway validates timestamps, logs records to local SQLite, calculates tri-domain risk heuristics, and stages sync records in an outbox.

STEP 03 // CLOUD & PWA

Remote Caregiver Oversight

Records sync to Cloud Firestore in real time. Authorized doctors and family members open the Progressive Web App on their phones or laptops to view live telemetry, ECG waveform traces, and longitudinal trends.

Completed & Verified Pipeline
  • ESP32 NTP Timestamps: Fixed timestamp 0 issue; firmware synchronizes via NTP and publishes valid Unix timestamps.
  • Raspberry Pi MQTT Broker: Local Mosquitto on port 1883 actively receives and validates sensor packets.
  • Cloud Firestore Sync: Outbox retry queue uploads patient records to patient_readings collection.
  • PWA Web Dashboard: Real-time onSnapshot streaming, Lead-I ECG strip monitor, and mobile touch interface.
Required Before Clinical Pilot
  • Reference Instrument Calibration: Benchmarking physical sensor accuracy against certified medical instruments.
  • Electrode Attachment & Motion Artifacts: Refining wearable ECG electrode placement and movement filtering algorithms.
  • Hardware Blood Pressure Integration: Integrating the UART cuff module for timed blood pressure capture.
  • Offline Endurance Testing: Stress-testing disconnected operations and high-volume local SQLite recovery.
  • Granular Security Rules: Hardening Firestore per-patient access control prior to patient trials.
